# 规格文档

本项目采用 SDD（Spec-Driven Development，规格驱动开发）。

`specs/` 负责记录项目规格：目标、行为、约束、验收标准，以及这些内容随实现变化后的同步更新。

## 文档职责

- `specs/architecture/*`：记录跨实验、长期有效的架构和流程约定。
- `specs/experiments/*`：记录单个实验的目标、体验、技术说明和验收标准。
- `docs/adr/*`：记录会影响后续开发的架构决策，以及选择它的原因和影响。

## 维护规则

- 新增有意义的功能或实验前，先新增或更新对应 spec。
- 当架构选择会影响后续开发时，使用 ADR 记录决策。
- 实现只围绕 spec 收敛，不顺手扩大范围。
- 当行为、约束或验收标准发生变化时，同步更新 spec。

## 文档语言

SDD 相关文档默认使用中文编写，方便长期阅读和复盘。技术名词、包名、命令、API 名称保持英文原文。

## 项目卫生

- 临时 debug 产物可以用于排查问题，例如 dev server log、error log、scratch 输出文件。
- 问题修复并验证完成后，必须清理这些临时产物，避免项目目录长期堆积无意义文件。
- 最终反馈中需要说明是否做了清理，以及清理了哪些类型的临时产物。

## 与 AGENTS.md 的关系

- `AGENTS.md` 是 agent 的仓库级工作指南，回答“agent 应该如何在这个仓库工作”。
- `specs/` 只负责维护 SDD 规格文档本身，回答“项目和实验应该满足什么规格”。
- 当规则同时影响 agent 执行方式和规格文档维护方式时，需要同步更新 `AGENTS.md` 和本文件。

# 规格文档

本项目采用 SDD（Spec-Driven Development，规格驱动开发）。

在实现一个有意义的功能或实验之前：

1. 在 spec 中记录目标、约束和验收标准。
2. 当架构选择会影响后续开发时，使用 ADR 记录决策。
3. 实现只围绕 spec 收敛，不顺手扩大范围。
4. 当行为发生变化时，同步更新 spec。

## 文档语言

SDD 相关文档默认使用中文编写，方便长期阅读和复盘。技术名词、包名、命令、API 名称保持英文原文。

## 项目卫生

- 临时 debug 产物可以用于排查问题，例如 dev server log、error log、scratch 输出文件。
- 问题修复并验证完成后，必须清理这些临时产物，避免项目目录长期堆积无意义文件。
- 最终反馈中需要说明是否做了清理，以及清理了哪些类型的临时产物。

## Agent 工作流

- 仓库根目录的 `AGENTS.md` 是 agent 的工作入口指南。
- agent 在执行非简单任务前，应先阅读 `AGENTS.md` 和相关 spec/ADR。
- 当 SDD 流程规则发生变化时，应同步更新 `AGENTS.md` 和本文件中对应的流程约定。
